# 目标岗深度理解（运维开发 / 容器平台）

> 2026-08-04 学员约定：FZ1 可以「先稳基础」，但**后续题与追问要加深岗位理解**，不能停在名词背诵。  
> 关联：`PROBE-PROTOCOL.md` · `STAGE-PORTRAITS.md` L3/L4 · JD 技能清单

## 1. 这个岗在面试官眼里是什么

不是「会 kubectl 的人」，更接近：

| 层次 | 期望 |
|------|------|
| L1 基础 | 对象、路径、排障口令说得清 |
| **L2 值班** | 线上怎么证伪、先看啥、和谁协作、怎么止血 |
| **L3 平台感** | 控制面/数据面边界、规模化瓶颈、扩展点（CRI/CNI/CSI/Device Plugin/Operator） |
| L4 定价 | 取舍、方案对比、变更风险、能带人扛故障 |

当前主目标 L3：**合面站得住** = L1 稳 + 大量 L2 + 若干 L3 深挖（混部或 Go 并发至少一头）。

## 2. 训练怎么加深（不另开赛道）

每题默认三层（先答 L1，过了再加压，一次 1～2 层）：

| 层 | 问法 | 例（运行时） |
|----|------|--------------|
| **L1 主线** | 链路/对比说清 | kubelet→CRI→containerd→runc/Kata |
| **L2 机制/对比** | 谁改写、为何、误用代价 | shim、RuntimeClass、共享内核 vs 独立内核 |
| **L3 生产/值班** | 怎么证、规模化坑 | 镜像拉取失败分层；Kata 指标为何不能只扫 Host |

FZ5/合面再叠：**故事 2～3 层追问、故障设计题、取舍题**（何时上 Kata / 何时 GPU 池 / 混部水位）。

## 3. 「更深刻的面题」从哪来

- JD：稳定性、运行时、扩展插件、大规模、Go 自动化  
- 面经：SNAT/跨主机、排障互判、调度混部  
- 你的经历：事件自动化、cgroup、CSI、Kata P 轨 — **深挖真实做过的，不编**

禁止：为了深而深到 L5（Raft 源码、自研 CNI）除非你点名或雷达连续高频。

## 4. 与 FZ 排期的关系

- FZ1：基础过线 **同时** 每题带 L2 追问；重点题（网络、运行时、调度）可到 L3 生产层  
- FZ2：几乎全是 L2/L3（排障即岗位核心）  
- FZ5：岗位理解最深的一段（混部/隔离）  
- 合面：跨域深题 + 愿意一起值班的量尺  

## 5. 引入新概念时的教法（2026-08-04 学员约定）

1. **先问「会不会 / 听过没有」**（或一句探测），不默认学员维护过该组件。  
2. **再庖丁解牛**：按层次拆（是什么 → 谁在用 → 对比 → 排障会碰到啥）。  
3. **不假装有运维经历**：无维护镜像仓等，只讲原理 + 排查时会看到的现象。  
4. 当前已知薄弱（按需插队补，仍挂 FZ1）：**镜像分层 / rootfs**、**containerd**、**镜像仓够用级**。

## 6. 组件深度对照（2026-08-05 · 防「全部深入」焦虑）

| 深度 | 组件 | 训练含义 |
|------|------|----------|
| 链路能讲清 | kubelet、apiserver、scheduler、etcd 定位、containerd、runc | FZ1 主线 |
| 机制+对比 | kube-proxy、CNI、cgroup/ns、overlayfs | FZ1 网络/镜像；FZ5 cgroup |
| 会用+边界 | controller-manager、CSI、Kata、Docker | 点到职责；经历深挖 |
| 后置 | etcd Raft、自研调度器、Mesh、数据库内核 | 默认不开 |

「计算机基础好」= OS/网络/并发在追问里能下钻一层，不单开无限计基课。
