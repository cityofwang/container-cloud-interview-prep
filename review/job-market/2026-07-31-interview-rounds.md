# 目标司面试轮次与流程（社区样本）2026-07-31

口令关联：`扫岗位` 补充情报（**非**官方承诺；组间差大）。  
用途：让你对「几面、每面考什么」有底，并对照仓库一面/二面/三面设计。  
**投递澄清（2026-08-04）：训练权重 = 多厂均衡（取消京东略加重）；轮次样本仍可参考下表各司流程。**

## 2. 总览（社招技术 · 容器/基架向粗口径）

| 公司 | 常见结构 | 你心里怎么记 |
|------|----------|--------------|
| **字节** | **3～4 轮技术** + **1 轮 HR**；部分有交叉面 | 偏「多轮技术」；基架/研发常带算法或硬基础 |
| **京东** | 多为 **2～3 轮技术** + **HR**；有的还有补充面/大 leader | 运维开发样例：测评分 → 一面双人(开+运) → 二面项目 → HR |
| **小红书** | 常 **2～3 轮技术** + **HRBP**；基架样例可 **3 技术且无 HR 面就 OC** | 基架偏**项目拷打**；业务后端更偏算法+系统+业务 |
| **阿里云/腾讯云（对照）** | 常 **2～4 轮技术** + HR；容器岗简历深挖重 | 与仓库「云厂商容器」对齐 |

**和仓库面次的对应（帮你有底）：**

```text
仓库「一面」≈ 各司第 1～2 轮技术里的「对象+排障+基础」
仓库「二面」≈ 经历深挖（混部/cgroup/CSI）+ 加压
仓库「三面/合面」≈ leader/交叉 + 取舍/容量/协作
编码过线     ≈ 字节/部分研发岗现场题；京东运维开发也可能轻手撕
```

你没社招经验：先把 **仓库一面短模过关** 当成「扛住第一轮技术」；二面预习包对应「同事说的丰富度」。

## 3. 分司摘要

### 3.1 字节跳动

- **轮次（社招技术常见）：** 一面 peer 基本功 → 二面直属 leader 项目/工程 → 三面部门 leader / 上限与匹配 → **可能交叉面** → HR。合计常 **3～4 技术 + HR**。  
- **每轮约：** 45～75min。  
- **容器/基架向题感：** K8s/容器隔离、大规模与排障、Go 并发；研发向常 **手撕算法**；纯运维向也可能少算法但 Linux/网络更狠。  
- **对你：** 算法按「过线」准备，别按算法岗；故事卡（混部/cgroup）要能追 2～3 层。

### 3.2 京东（含科技/云/运维开发样本）

- **轮次样本：**  
  - 前端社招例：小 leader → 技术二面 → 补充面 → 大 leader（后两轮偏流程感）  
  - 运维开发 Offer 例：测评 → **一面（开发+运维双人）** → 二面项目/闲聊 → **HR** → OC  
- **容器题感（运维开发面经）：** Docker 隔离/限制、网络 SNAT/DNAT、Service/iptables、跨主机通信、Linux 基础、Dockerfile；二面相对轻。  
- **对你：** 与当前 FZ1 + 排障路径高度同频；Go 仍要过线。

### 3.3 小红书

- **业务/后端综述：** 常 **2～3 技术 + HRBP**；校招多笔试。  
- **基础架构样例（对象存储向个人面经）：** **三轮技术**，主打项目拷打，八股/算法相对少；有人 **无 HR 面直接 OC**。  
- **云原生/K8s 向社区说法：** Pod/Deploy/Service 要结合生产；高可用、调度、探针、混部/利用率；了解 OpenKruise 等为加分。  
- **对你：** 若投基架/云原生，优先练 **STAR + 混部/CSI/事件**；若投偏业务后端，算法和系统设计权重上升（与当前策略 D 需取舍）。

### 3.4 阿里云 / 腾讯云（对照）

- 容器/弹性计算等：多轮技术，**简历深挖 + K8s/Linux/Go**；有的轮次广、有的手撕。  
- 云计算方向总结常见：cgroup/namespace、scheduler 流程、Informer、偶发 Raft（加分）。

## 4. 对你投递的实操建议

1. **均衡投递：** 按「2～3 轮技术 + HR」等各司样本分别准备；短模按 JD 缺口抽题，不因某司多抽。  
2. **广覆盖不缩水**：字节（多轮/算法余量）、小红书（项目拷打）、云厂商容器 —— 仍按 FZ 与题包推进。  
3. 邀约时问 HR：`一共几轮技术？有没有交叉面/笔试？本轮偏运维还是研发？`  
4. 训练节奏：FZ1 短模过关 → FZ2/故事深挖 → Go → 合面。
