## 扫描结论（一句话）

国内运维/运维开发向：**Docker 出网 SNAT → DNAT（Service）→ Pod 跨主机（VXLAN/VTEP 或 host-gw）** 是一条几乎必问的链路；再往下常追 **veth/bridge、kube-proxy 链、iptables vs IPVS、externalTrafficPolicy**。

## 推荐特训顺序（先题后原理）

1. **出网与回包**：容器访问外网为何要 SNAT（京东同构开场）
2. **入站发布**：DNAT 与 Service/NodePort 同构
3. **同节点**：netns + veth + bridge（L2）
4. **跨节点**：VXLAN/VTEP vs host-gw/BGP（对比表）
5. **Service 数据面**：KUBE-SERVICES → SVC → SEP；何时还要 SNAT
6. **排障口令**：不通先 Endpoints；再 DNS/规则/抓包
7. **进阶**：IPVS、externalTrafficPolicy、NetworkPolicy 边界

## 面试官爱听的对比句（特训目标口径）

- Docker 默认跨主机常靠 NAT；**K8s 模型要求 Pod IP 跨节点直达，跨节点路径本身不做 NAT**（封装或路由）。
- **SNAT 改源、DNAT 改目的**；出网常见 SNAT，Service 入站常见 DNAT；跨节点回包/NodePort 等场景仍可能 SNAT。
- **kube-proxy 写规则，不经用户态转发流量**（现代模式）。
- IPVS 做转发快，**SNAT/NodePort 等仍常依赖 iptables**。
